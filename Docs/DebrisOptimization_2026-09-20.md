# 잔해(부서진 소품) 최적화 — 면접 설명용 (2026-09-20)

코드: `Source/ProjectPG/Public/Common/PGDebrisSubsystem.h`, `Private/Common/PGDebrisSubsystem.cpp`, `Private/Common/PGPhysicsUtil.cpp`
비교 스위치: `PG.Debris.Legacy 1` = 예전 방식(부술 때마다 새로 만들기 + 전부 Chaos 물리)

---

## 0. 한 줄 결론

> **객체 풀이 중심이고, 그 위에 "물리 예산 · 잠재우기 · 프레임 나누기 · 로딩 때 미리 하기" 네 가지를 얹었다.**
> 메모리 풀을 따로 만든 게 아니라, 객체를 재사용하니까 메모리도 자연히 재사용되는 것이다.

결과(사용자 PIE 관찰): 로봇으로 공장을 부수는 동안 **Frame 15.9 ms / Game 12.9 ms**. 예전에는 최대 **Game 81 ms**, 직전 PIE 에서 38~46 ms.

## 1. "객체 풀이야? 메모리 풀이야?" — 먼저 구분

```
메모리 풀  = "빈 메모리 칸"을 미리 잡아 두고 new/delete 대신 칸을 빌려줌   ← 할당기 수준 (UE 는 엔진 할당기가 이미 함)
객체 풀    = "다 만들어진 물건(액터+컴포넌트)"을 미리 만들어 두고 빌려줌   ← 게임 로직 수준  ★ 이번에 한 것
```

- 이번 코드는 **객체 풀**이다. 판 시작 때 액터 40개(`PG.Knock.MaxAlive`)를 **완성품으로** 만들어 둔다: 액터 + 물리 상자(`DebrisBox`) + 보이는 메시(`DebrisVisual`), 등록까지 끝낸 상태.
- 객체를 버리지 않고 계속 쓰니 **새 메모리 할당도 없고, GC(가비지 컬렉터)가 치울 쓰레기도 안 생긴다** → 이게 "메모리 재사용"의 실체. 할당기를 직접 만든 건 아니다.
- **정직하게 말할 부분**: 풀이 없애는 건 `SpawnActor` · `NewObject` · `RegisterComponent`(씬·물리 등록) · GC 비용이다. **메시를 갈아 끼우는 비용(`SetStaticMesh` → 렌더 상태 다시 만들기)은 남는다.** 그래서 풀 하나로 끝내지 않고 아래 네 가지를 같이 썼다.

## 2. 왜 필요했나 (측정 → 원인)

```
공장·선반을 로봇이 밀면 한 프레임에 소품 수십 개가 걸림
 → 하나마다: 액터 새로 만들기 + HISM 인스턴스 제거 + Chaos 물리 몸 + 움직이는 그림자
 → 프레임이 뚝 떨어짐 (MaxAlive 120 일 때 Game 81 ms)
 → Unreal Insights / stat namedevents 로 찍어 보니 대부분이 Chaos Collisions::NarrowPhase
    (큰 상자가 건물의 복잡한 충돌 = 삼각형 수천 개와 맞닿아 상자-삼각형 비교가 폭발)
```

`TRACE_CPUPROFILER_EVENT_SCOPE(PGDebris_Launch / PGDebris_Tick / PGKnock_SpawnProxy / PGKnock_RemoveInstance …)` 를 넣어 두어서 Insights 에서 이름으로 비용을 볼 수 있다.

## 3. 다섯 가지 기법 (무엇을 · 왜 · 코드 위치)

### ① 객체 풀 — "만들지 말고 빌려 쓴다"
- **무엇**: `OnWorldBeginPlay` 에서 40개 미리 생성 (`CreatePooledActor`). 부술 때는 `Launch` → `AcquirePiece` 로 빈 조각을 빌리고 **메시·재질만 바꿔 끼운다**.
- **풀이 꽉 차면**: 가장 오래된 조각 중 **화면에 안 보이는 것**(`WasRecentlyRendered(0.3)` 이 false)을 먼저 회수. 전부 보이면 그냥 가장 오래된 것(최후의 수단).
- **반납**: `Deactivate` — 물리·충돌 끄고, 메시를 `nullptr` 로 비워 렌더 자원을 놓고, 숨겨서 지하(-100000)로 보냄. 파괴(Destroy)하지 않는다.
- **왜**: 부술 때마다 생성·등록 비용이 한 프레임에 몰리던 것을 없애려고.

### ② 물리 예산(시뮬레이션 LOD) — "진짜 물리는 동시에 12개까지만"
- **무엇**: `CountSimulating() < PG.Debris.MaxPhysics(12)` 이면 Chaos 진짜 물리(`StartPhysics`), 넘치면 **직접 짠 가벼운 움직임**(`TickFly`).
  - 가벼운 움직임 = 중력, 공기 저항, 바닥 튕김, 마찰, 빠를 때만 진행 방향 선 트레이스 1개로 벽 반사, 느려지면 **가장 넓은 면으로 눕히기**(`PickRestAxis`).
  - 큰 판·나무(`CollapseRadius` 300 cm 초과)는 처음부터 물리 없이 **넘어지기**(`TickTip`): 밀린 쪽 **바닥 모서리를 경첩**으로 90도 눕는다(원점 기준으로 돌리면 땅에 박혀 보였음).
- **왜 둘을 섞었나**: 사용자 피드백 — "진짜 물리끼리 부딪히는 게 더 자연스럽다". 그래서 **평소(차로 몇 개 칠 때)는 전부 진짜 물리**, 공장이 통째로 무너질 때만 넘치는 분을 흉내로 넘긴다. 잔해끼리 충돌(`PG.Debris.SelfCollide`)도 동시 12개뿐이라 켜 둘 수 있게 됐다(예전엔 120개가 겹친 채 태어나 겹침 풀기가 폭발해서 꺼야 했다).
- **이름 붙이기**: 게임 업계에서 흔한 "시뮬레이션 LOD / 예산(budget)" 방식. 중요한 것(적은 수)만 비싼 계산, 나머지는 싼 근사.

### ③ 잠재우기(Sleeping) — "멈춘 조각은 비용 0"
- **무엇**: 진짜 물리 조각이 0.5초 가만히 있거나(속도 30 cm/s·각속도 45°/s 미만) 6초(`PG.Debris.PhysicsSeconds`)가 지나면 `StopPhysics` → **질의 전용(QueryOnly), 물체 종류 WorldDynamic, 모든 응답 Ignore** 인 "누워 있기" 상태.
- **다시 깨우기**: 차·탱크·몬스터가 앞을 **물체 종류(Object Type) 스윕**할 때 잡히면 `TryKnockProp` → `Kick` 으로 다시 움직인다. 작은 것은 예산이 남으면 진짜 물리로, 아니면 가벼운 움직임으로.
- **왜 응답이 전부 Ignore 인데 스윕에 잡히나** (꼬리질문 대비): 물체 종류 질의는 **응답 설정을 보지 않고 물체 종류만 본다**(엔진 `CollisionQueryFilterCallback.cpp` 확인). 그래서 **물리로는 아무것도 막지 않으면서도 "차에 치일 수는" 있다.**
- 같은 조각을 0.25초 안에 다시 치지 않는다: 로봇이 매 Tick 스윕해서 발밑 잔해를 로켓처럼 쏘아 올린 버그 대책.

### ④ 프레임 나누기(Time-slicing) — "한 프레임에 몰지 않는다"
- **무엇**:
  - 새 잔해는 프레임당 `PG.Knock.PerFrame`(4)개까지 (`TakeSpawnBudget`). 넘치면 그 소품은 **그대로 남고 다음 프레임 스윕이 다시 잡는다** → 눈에는 "연달아 무너지는" 것으로 보여서 오히려 자연스럽다.
  - 바닥·벽 트레이스는 프레임당 64개까지(`MaxTracesPerFrame`). 바닥은 옆으로 1 m 넘게 움직였을 때만 다시 찾는다.
  - 먼지 이펙트는 0.12초에 하나.
- **왜**: 평균이 아니라 **최악의 한 프레임(스파이크)**이 끊김으로 보이기 때문.

### ⑤ 미리 데우기(Prewarm) — "첫 사용 비용을 로딩 화면으로"
- **무엇**: 풀 생성과 먼지 이펙트 1회 재생(보이지 않는 곳, 크기 0.01)을 **검은 로딩 화면 동안** 한다.
- **왜**: 파티클·셰이더는 처음 쓸 때만 비싸다. 처음 부수는 순간만 끊기던 것을 로딩으로 옮김.

### (덤) 렌더링·길찾기 비용 빼기
- 작은 잔해(반크기 120 cm 미만)는 **그림자 끔**: 움직이는 작은 그림자 수십 개가 Virtual Shadow Map 페이지를 계속 다시 그리게 했다.
- **Lumen 거리장·간접광에서 제외**(`SetAffectDistanceFieldLighting(false)`): 날아가는 메시가 매 프레임 거리장을 갱신하게 만들었다(GPU 측정).
- **길찾기 지도에 안 넣음**(`SetCanEverAffectNavigation(false)`): 움직일 때마다 내비 타일을 다시 구웠다. 캐릭터가 밟고 올라서지도 못하게(`CanCharacterStepUpOn = ECB_No`) — 보스가 잔해를 밟고 하늘로 튄 버그.

### (덤) 보기 좋게 만든 것
- 수명(25초)이 다하면 **화면에 안 보일 때 조용히** 회수, 계속 보이면 15초 더 기다렸다가 0.4초 동안 **작아지며** 사라짐(땅으로 가라앉히지 않음).
- 선반이 부서지면 그 위 아이템을 바닥으로 내림(`DropSupportedItems`) — 아이템이 공중에 줄지어 떠 있던 버그.

## 6. 예상 꼬리질문과 답

| 질문 | 답의 핵심 |
|---|---|
| 풀 크기 40은 어떻게 정했나? | 120 에서 Game 81 ms. 굳히기·잔해끼리 무충돌을 넣고 40 으로 낮춤. 콘솔 변수라 기기별로 조정 가능(`PG.Knock.MaxAlive`, 8~128 클램프) |
| 풀이 꽉 차면 눈앞에서 사라지지 않나? | 안 보이는 것부터 회수(`WasRecentlyRendered`). 전부 보일 때만 가장 오래된 것 |
| 왜 전부 Chaos 로 안 했나? | NarrowPhase 가 병목(측정). 동시에 12개로 제한하면 자연스러움은 유지, 비용은 상한이 생김 |
| 가짜 물리는 부자연스럽지 않나? | 평소엔 전부 진짜 물리. 한꺼번에 무너질 때만 넘치는 분이 흉내. 큰 판은 경첩으로 넘어지게 해서 땅에 박히지 않음 |
| 응답이 Ignore 인데 어떻게 다시 칠 수 있나? | Object Type 질의는 응답 설정을 안 봄(엔진 소스 확인) |
| GC 는? | 풀 액터를 `UPROPERTY(Transient) TArray<TObjectPtr<AActor>> PoolActors` 로 잡아 GC 가 안 치움. 반납 때 Destroy 하지 않으니 GC 대상 쓰레기도 안 생김 |
| 멀티플레이면? | 서버는 "무엇이 부서졌나"만 ID 목록으로 복제, 잔해 연출은 각 클라가 자기 풀로(FinalePlan 12절 설계). 잔해 위치는 PC 마다 달라도 됨(보기용) |
| 개선 효과를 어떻게 증명하나? | `PG.Debris.Legacy 1/0` 로 같은 시드(`-PGMapSeed`)·같은 경로에서 A/B + Insights 트레이스 |

## 7. 알려진 한계 / 다음 개선 후보 (정직하게 말할 수 있게)

- **숫자 근거가 아직 약하다**: 15.9 / 12.9 ms 는 사용자 한 번 관찰. 면접 전에 `-PGMapSeed` 고정 + `PG.Debris.Legacy` A/B + Insights 캡처를 남겨 두면 좋다.
- 메시 교체(`SetStaticMesh`)의 렌더 상태 재생성 비용은 풀로도 안 없어진다.
- 작은 선형 탐색들: `FindPiece`·`CountSimulating` 은 매번 40개 순회(N=40 이라 문제는 안 됨), `KnockCVar` 는 호출마다 콘솔 변수를 이름으로 찾음.
- `DropSupportedItems` 는 부술 때마다 맵의 바닥 아이템 액터 전체(수백 개)를 순회한다. 한꺼번에 무너질 때 비용이 될 수 있음 → Insights 의 `PGKnock_DropItems` 로 확인.
- 트레이스마다 풀 액터 40개를 무시 목록에 넣는다.

## 7-2. 멀티에서 다시 잰 것 (9/28)

전용 서버 + 접속자 2명(한 명은 8배 로봇으로 중앙 건물을 부수며 지나가고 한 명은 70m 옆에서 봄), 접속자는 화면 밖 그리기로 실제 GPU 까지 쟀다
(`PG.SmashCoreTest` + `PG.NetSmashTest` — 1초마다 프레임·게임·렌더·GPU 시간과 잔해 수).

| 문제 | 원인(잰 것) | 해결 | 결과 |
|---|---|---|---|
| 구경하는 사람 화면에 부서진 벽이 남음 | 부수기 알림을 하나씩 "신뢰 안 함" 으로 보냄 → 엔진이 복제 한 번에 2개만 보내고 나머지를 버림. 서버 160개 중 1초 2개만 도착 | `APGKnockRelay` 가 프레임마다 묶어 신뢰 전송, 받는 쪽은 프레임당 4개씩 따라 함 | 174 / 174 도착 |
| 부수는 사람 화면이 25fps 로 떨어짐 | 계산이 아니라 그리기: 따라 하기 계산은 조각당 약 0.7ms(프레임당 1ms 남짓). 그림자·먼지를 끄는 비교에서는 차이 없음. 건물 앞에 서 있기만 해도 GPU 31ms, 부수면 38~40ms. 중앙 건물 레벨에 그림자 드리우는 전등 52개 | 시설 레벨이 뜰 때 점·스포트 전등 그림자 끔(`DA_PGMapVisuals` 의 `FacilityShadowLights`) | 부수는 동안 GPU 30~33ms, 최장 프레임 60 → 46ms |
| 드래곤 등장(땅 붕괴) 첫 1초 끊김 | GPU 83~88ms — 떨어지는 20m 땅판 수천 장의 그림자·간접광을 매 프레임 다시 그림 | 떨어지는 조각(임시 ISM)은 그림자·거리장·간접광 제외 | 붕괴 3초 최장 84.9 → 51.9ms, 평균 115 → 134fps |

면접 포인트: **"느린 곳을 먼저 갈랐다"** — 게임·렌더·GPU 시간을 따로 찍고, 가설(그림자·먼지·부수기 계산)을 하나씩 꺼 보는 비교로 좁혔다.
