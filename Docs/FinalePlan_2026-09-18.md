## 0. 한 줄 요약

워존 보스(8배 변기 로봇)를 쓰러뜨리면, 맵 외곽 타일을 부수며 **우주전함이 강하**한다. 플레이어가 전함에 **탑승하면 이륙**하고, 그 순간 **맵 외곽의 산이 갈라지며 드래곤이 솟아올라** 하늘에서 전함과 싸운다. 드래곤을 쓰러뜨리거나 버티면 **탈출 성공**.

탈출 게임(타르코프식) 규칙 안에 넣는다: 이건 "워존 보스를 잡은 사람만 여는 숨은 탈출 루트"다. 장르가 튀는 게 아니라 **최종 보상**이다. 면접에서 "왜 탈출 게임에 우주전함?"이라고 물으면 이 문장으로 답한다.

## 1. 왜 하나 (포트폴리오 관점)

- 영상 한 방: 외곽이 무너지며 전함이 내려오는 장면은 포트폴리오 영상의 마지막 컷이 된다.
- **핵심은 연출이 아니라 "기존 시스템 조합"이다.** 새로 만드는 것보다 이미 만든 것을 엮는 비중이 크다:

| 피날레 단계 | 재사용하는 기존 시스템 | 파일 |
|---|---|---|
| 보스 처치 감지 | 몬스터 사망 → 리스폰 기록부(RecordRobot) | `Private/Combat/PGMonsterRespawner.cpp`, `PGRobotCharacter` |
| 외곽 타일 부수기 | 넉 프록시(인스턴스 하나 떼어 물리로 날리기, 프레임 예산) | `Private/Common/PGPhysicsUtil.cpp` `TryKnockProp` |
| 탑승 | 탈것 공통 탑승/하차(Seat, Possess, IPGRideable 문구) | `PGVehiclePawn`, `PGTankPawn`, `Public/Interaction/PGRideable.h` |
| 드래곤 표적·반응 | 플레이어 우선 표적 점수, 30% 규칙 표적 고정, 표면 거리 공격 판정 | `MonsterAIController::TargetScore/ShouldSwitchTarget`, `PGMonsterCharacter::DistanceToTarget` |
| 산 갈라짐·파편 | 큰 조각 "무너지기"(물리 없음), 작은 파편만 물리 | `PGPhysicsUtil` `SpawnCollapseProxy` / `SpawnKnockProxy` |
| 탈출 성공 | 탈출구 완료 이벤트(OnExtractionCompleted) | `PGExtractionZoneActor` |
| 포격 | 탱크 주포(선 트레이스 + 범위 피해 + 소품 날리기) | `PGTankPawn::FireMainGun/Explode` |

면접에서는 "피날레를 위해 새로 짠 코드는 상태 기계 하나와 괴수 패턴뿐이고, 나머지는 이미 있던 시스템을 조합했다"고 말할 수 있어야 한다. 그게 설계 역량이다.

## 2. 흐름 (상태 기계)

`APGFinaleDirector` 하나가 서버에서 상태를 들고 복제한다. 상태마다 "들어갈 때 할 일 / 끝나는 조건"만 있다.

```
Idle ──(보스 사망)──▶ Warning(30초) ──▶ Arrival(전함 강하 ~15초) ──▶ Boarding(최대 45초)
                                                                        │ 전원 탑승 또는 시간 끝
                                                                        ▼
                   Victory ◀──(드래곤 체력 0 / 90초 버팀)── DragonFight ◀── Launch(이륙 10초)
                   Failure ◀──(전함 체력 0)──┘
```

| 상태 | 들어갈 때 | 끝 조건 |
|---|---|---|
| Warning | 화면 문구 "하늘에서 무언가 내려온다…", 카메라 미세 흔들림, 강하 지점 결정(아래) | 30초 |
| Arrival | 전함 액터 스폰(맵 밖 상공), 정해진 경로로 강하. 경로 앞을 스윕해 외곽 타일·나무·바위를 넉 | 착지 |
| Boarding | 램프 문 열림 = 탈출구 액터(Interact, 요구 아이템 없음) 활성 | 탑승자 전원 or 45초 |
| Launch | 램프 닫힘, 상승, 카메라를 전함 외부 추적으로 | 10초 |
| DragonFight | 외곽 산에서 드래곤 등장(13절), 전함 무기 사용 가능 | 드래곤 체력 0 or 90초 |
| Victory | 탑승자 전원 OnExtractionCompleted | — |
| Failure | 전함 추락 연출(선택), 탑승자 사망 처리 | — |

- **강하 지점**: 맵 가장자리 도로 끝(탈출 지점과 같은 규칙, `SpawnExitSet` 의 "바깥쪽" 계산 재사용) 중 보스 위치에서 가장 가까운 곳. 플레이어가 달려갈 거리가 너무 멀지 않게.
- **멀티**: 상태·타이머는 서버만 정하고 `ReplicatedUsing` 으로 클라가 연출만 따라간다(기존 오브젝트와 같은 규칙).

### 4-1. 드래곤 (DragonFight) — 9/19 결정

에셋: Fab **"Dragon for Boss Monster : PBR" (Dungeon Mason, 무료)** → `/Game/FourEvilDragonsPBR` (받음). 4종 × 애니메이션 16~18개, 한 마리 약 4~5천 삼각형이라 **8GB 에서 가장 가벼운 선택**이다(385CY·KitBash 같은 영화용 에셋의 반대).

| 드래곤 | 날기 | 쓸 곳 |
|---|---|---|
| **Usurper** (본 보스) | O — Scream, TakeOff, FlyIdle/Forward/Glide, **FlyFlame**, Land, AttackFlame/Hand/Mouth, GetHit, Die | 유일하게 **날면서 불 뿜기**가 있다 → 공중의 전함을 공격하기에 맞다 |

- 스킨: PBR 4색 중 맵(사막·공장)과 대비되는 색. Handpainted 판은 쓰지 않는다(만화풍).
- **Dragon Cave(Fab) = 추가 목표(9/19 사용자 결정)**: 프레임 예산(4060)이 남으면 "외곽에서 동굴이 솟아오르고 그 안에 사는 드래곤을 전함으로 끌어내 공중전 → 처치 보상(좋은 아이템)"으로 확장한다. 전장은 동굴 안이 아니라 하늘이다(동굴 = 등장 무대). 안 되면 **대안: 외곽(산 배경) 바닥 타일을 부수며 드래곤이 땅에서 솟아오른다** — 꺼지는 타일 위 오브젝트는 같이 "무너지기"로 처리(13절).
- 원래 판단(참고): 전함과 드래곤이 날아서 싸우려면 넓은 하늘이 필요한데, 동굴 안에서 하면 동굴을 맵만큼 키워야 하고 영화급 환경이라 8GB 에서 무겁다. 전장은 600m 맵 위 하늘이다.

## 5. 팀원에게서 "숨기기" → 실제로는 **분리**

솔직한 권장: 팀 저장소에 몰래 넣는 건 나중에 들키면 신뢰 문제고, 머지 충돌의 원인이 된다. **숨기는 게 아니라 처음부터 섞이지 않게 분리**하면 결과적으로 팀원은 모른다.

1. **저장소 분리 (이미 되어 있음)**: 피날레는 `D:\ProjectTest2` + 개인 레포(`Tools\personal-git.bat`)에만. 팀 레포(`D:\ProjectPG`, `.git`)에는 커밋하지 않는다. 팀 이식(원래 목록 3번) 때 피날레 파일은 옮기지 않는다.
2. **폴더 분리**: 코드 `Source/ProjectPG/{Public,Private}/Finale/`, 에셋 `/Game/PG/Finale/` 와 `/Game/PG/Vehicles/Battleship/`. 이식할 때 이 폴더만 빼면 끝.
3. **스위치**: 설정 `UPGObjectSettings::bEnableFinale`(기본 true, 개인 빌드), 기존 `bSpawnHiddenTank` 와 같이. 코드가 섞여 들어가도 꺼져 있으면 아무 일도 안 일어난다.
4. **의존 방향**: 기존 코드 → 피날레 코드 호출은 **딱 한 곳**(보스 사망 알림). 그 한 줄을 `#if`/설정 체크로 감싼다. 피날레 폴더를 지워도 컴파일이 되게.
5. 팀 프로젝트에도 넣고 싶어지면 그때 팀에 보여 주고 합의 후 넣는다. 영상으로 보여 주면 설득이 쉽다.

## 6. 8GB VRAM 에서 돌아가게 (최적화 계획)

**기준: 학원 PC(RTX 4060 8GB)에서 무리 없이.** 팀원도 이 에셋·코드를 가져다 쓴다. 집 PC(RTX 5060 Ti 16GB)에서 잘 돈다는 건 증거가 아니다. 대략 4060 은 5060 Ti 의 60~70% 로 보고, **집 PC GPU 10ms 이하 = 4060 에서 60fps 근처**를 1차 목표로 잡는다(최종 확인은 학원 PC).

학원 PC 현실: VRAM 8GB, `r.Streaming.PoolSize` 는 프로젝트 2048 / 학원 PC 는 문서 폴더 `UserEngine.ini` 에서 1500. 원칙: "필요할 때만, 필요한 만큼만".

## 12. 멀티·서버 (9/19 추가)

- **전용 서버는 화면을 그리지 않는다.** GPU·Lumen·그림자는 클라 몫이고, 서버 예산은 게임 로직(AI·이동·판정·물리)이다. 서버 틱 목표 30Hz(33ms).
- **파괴는 서버가 "무엇이 부서졌나"만 정하고, 잔해는 클라 연출**로 나눈다. 9/19 에 찾은 병목(Chaos 충돌 계산)을 서버가 떠안으면 안 된다.
  - 서버: 부서진 것을 **ID 목록**(셀 좌표 + 배치 번호 + 생성 때 붙인 인스턴스 번호)으로 기록·복제. HISM `RemoveInstance` 뒤 인덱스는 바뀌므로 ID 로 쓰지 않는다(Epic "The Player was Here" 발표 p13–15).
  - 클라: ID 를 받으면 각자 `PGPhysicsUtil` 로 잔해·무너지기 연출. 잔해 위치는 PC 마다 달라도 된다(보기용).
  - 늦게 들어온 클라·다시 로드된 시설 레벨: 로드될 때 ID 목록을 다시 적용.
- 드래곤·전함 위치·체력·상태는 서버가 정하고 복제(`ReplicatedUsing`), 애니메이션·불꽃은 클라.
- 지금 코드는 멀티 구조가 아직 없다 → **팀 코드 합칠 때 같이 설계**(팀 쪽 서버 구조에 맞춤).

### 14-2. 상태 기계 (지금 코드 그대로)

```
Idle ─(보스 사망 / PG.Finale.Start)─▶ Warning(15초) ─▶ Arrival ─▶ Hover ─▶ Launch ─▶ Dragon ─▶ Victory
```

| 상태 | 들어갈 때 | 다음으로 넘어가는 조건 |
|---|---|---|
| Warning | 로그만. 끝나기 **3초 전**에 미리 만들어 둔 전함을 산 너머에서 보이게 한다(첫 렌더 비용을 아무도 안 볼 때 치른다) | `WarningSeconds`(기본 15초, 기획서 30초는 확인이 답답해 줄임) |
| Arrival | 전함이 산줄기 바깥 500m·높이 400m 지점에서 정박 지점으로 순항(60m/s, 약 15초) | 전함이 `OnArrived` 알림 / 60초 지나면 강제로 정박(껍데기 팩이 없는 PC 에서 멈추지 않게) |
| Hover | 정박 위치는 **맵 외곽(타일 끝 95%)**, 밑바닥 높이 120m. 승강 발판을 땅까지 내린다 | 갑판 높이·배 길이 안에 사람이 **3초** 서 있음(`IsAnyoneAboard`) / `PG.Finale.Launch` |
| Launch | 정박 높이 +300m 로 상승. 올라가는 동안 배 밑 소품·타일을 **프레임당 4개씩만** 날린다 | 목표 높이 도착 / 25초 |
| Dragon | 드래곤 스폰(맵 외곽 산 쪽, 땅 90m 아래에서 시작) | 드래곤 체력 0(`IsDead`) |
| Victory | 로그. 탈출 완료 이벤트 연결은 아직 없다 | — |

- **왜 Boarding 을 따로 두지 않았나**: 기획서의 램프 문 탈출구 액터 대신 "갑판 위에 3초 서 있으면 출발"로 줄였다. 문·상호작용·타이머를 새로 만들지 않고 이미 있는 위치 판정으로 끝난다. 탑승 경로는 두 가지 — 승강 발판(걸어서) 또는 날으는 차(뒤쪽 열린 격납고로).
- **왜 Failure 가 없나**: 전함 `TakeDamage`·체력은 있지만 0 이 됐을 때의 추락 연출·사망 처리는 안 만들었다(14-8).
- **미리 만들기(`Prewarm`)**: 보스가 죽은 뒤 전함을 만들면 부품 31개 + 재질·텍스처 읽기가 그 프레임에 몰려 화면이 끊겼다(9/20 PIE "등장할 때 순간 렉"). 그래서 판을 만들 때(보스를 놓을 때) 만들어 산 너머에 숨겨 둔다. 등장 순간은 "이미 있는 것을 움직이기"뿐이다.

### 14-3. 전함

**크기.** 배율 1 화물선을 잰 값이 둘 있다 — 부품 치수 스크립트(`measure_minerva_parts.py`) 기준 **길이 41.0 × 폭 16.6 × 높이 16.9m**, 조립 뒤 런타임 껍데기 상자(`HullBounds`) 기준 **약 43.6m**(튀어나온 부품 포함). 배율 10 이라 **410~436m**, 20m 타일 20칸이 넘는다. 기획서 60~80m 목표(배율 1.5~1.9)는 사용자가 9/20 에 "10배, 하늘을 덮는 크기"로 바꿨다. `PG.SpawnBattleship 1 60` 처럼 띄워 보고 고른 값이다.

**설계 결정과 이유**

1. **껍데기는 눈, 상자는 발.** 10배로 키운 팩 메시의 충돌을 그대로 쓰면 (a) 움직이는 액터에 삼각형 수십만짜리 복잡 충돌이 붙어 Chaos 가 매 프레임 다시 넣었다 뺐다 하고(잔해 때 겪은 NarrowPhase 자리), (b) 팩의 단순 충돌은 통짜 상자라 복도 안으로 못 들어간다. 그래서 껍데기 전 부품은 `NoCollision` + 그림자 끔(436m 짜리 동적 그림자는 그림자 맵을 통째로 다시 그린다), 발이 닿는 곳은 우리가 놓은 `UBoxComponent`(`WalkBoxes`)뿐이다. 스폰 직후 1초 동안 10배 복합 충돌이 살아 있던 것도 막았다.
2. **속은 따로 배율 1.** 껍데기를 10배로 키우면 팩 내부 부품도 10배라 사람이 개미가 된다. 그래서 **갑판**(두 장 — 승강로 자리를 비워야 올라오는 사람이 갑판에 파묻히지 않는다, 오후에 3배 두껍게), **격납고**(RoverGarage, 뒤쪽을 열어 날으는 차가 들어온다), **복도**(PropTunnel), **함교**, **승강 발판**을 배율 1 로 따로 놓는다. 사용자 요구 "내부 구현까지 우주전함을 진짜 타는 느낌".
3. **함교는 뱃머리 유리창(BodyFrontGlass) 안쪽.** 유리 위치는 껍데기 부품을 이름으로 찾아 런타임에 잰다(`FindHullPartLocal`). 1인칭(V 키, 카메라 팔 길이만 0 — 팀 카메라 구조는 그대로)으로 보면 진짜 창밖이 보인다 — 화면을 한 번 더 그리는 렌더 타깃과 달리 비용 0. 함교 키트(모델링 세션: 콘솔·캐노피·의자, 장갑판·리벳·기름때 텍스처 2048 6장, ORM 텍스처가 거칠기·금속 담당)로 팩 임시 부품을 교체했다. 고도·속도·상태·갑판 높이는 `UTextRenderComponent` 월드 글자로 콘솔 앞에 띄운다(UMG 를 안 써서 팀 UI 와 안 겹친다). 콘솔 화면 슬롯 3개(인덱스 3·4·5)에는 **후방 카메라 렌더 타깃 하나**(512×264)를 물린다 — 진짜 카메라는 1대뿐이고, 초당 12장·40m 안에 사람이 있을 때만 찍는다(화면을 한 번 더 그리는 일이라 비싸다).
4. **조립이 끝나기 전에는 움직이지 않는다.** 팩 부품은 전부 `Static` 이라 움직이는 액터에 붙지 않는다(로그: *"is not static, cannot attach ... Aborting"*). 스폰 → 1초 기다림 → 부품 31개를 `Movable` 로 → 크기 측정 → 그제야 출발(`bPendingCruise`).
5. **움직임은 탱크와 같은 코드 이동.** 목표점으로 일정 속도, 도는 만큼 기울임(`MaxBankDeg` 8도). 물리로 띄우면 436m 질량체가 떨린다. 정박 중 위아래 흔들림은 50cm → **12cm**(얇은 갑판 + 큰 흔들림이면 내려앉은 차가 갑판을 뚫었다).
6. **승강 발판**: 120m 를 1400cm/s 로 약 9초. 발판 위 사람은 UE `MovementBase` 로 같이 올라간다. 탑승 감지는 "겹침"이 아니라 "발판 위 공간 검사"(막는 상자 위에 선 캐릭터는 2cm 떠 있어 영원히 안 겹친다). 갑판에 올라간 뒤 비면 다시 내려온다.

**무기 (조종석 `HelmZone` 안에 서 있어야 내 것이 된다, 조준 = 화면 가운데)**

| | 주포 (좌클릭) | 유도 미사일 (우클릭) |
|---|---|---|
| 방식 | 탱크 `FireMainGun/Explode` 그대로 — 선 트레이스 즉시 명중 + 범위 피해 | 코드 이동 + 초당 70도 제한 유도 + 프레임당 선 트레이스 1개 |
| 수치 | 포구 3문 번갈아, 장전 1초, 사거리 600m, 직격 900 + 범위 1400(반지름 15m) | 좌우 포구 2발, 간격 2.5초, 직격 1500 + 범위 2000(반지름 25m), 30→90m/s, 9초 뒤 자폭 |
| 연출 | 가발 광선 메시를 포구~탄착점으로 늘림(탱크는 디버그 선만) | 전용 메시(본체·꼬리 불꽃·폭발 구). 폭발은 파티클 대신 구 껍질을 0.3초 부풀리기 |

둘로 나눈 이유: **하늘을 나는 드래곤을 즉시 명중으로 맞히면 공중전이 되지 않는다.** 미사일은 급하게 못 돌아서 드래곤이 크게 돌면 피할 수 있다.

### 14-4. 미사일 객체 풀 — 왜 잔해 서브시스템과 같은 구조인가

`UPGMissileSubsystem` 은 `UPGDebrisSubsystem` 을 그대로 본떴다. 판 시작에 24발을 만들어 두고 꺼내 쓰고 돌려받으며, 풀이 비면 **가장 오래된 것을 거둬 쓴다**(잔해와 같은 규칙). 이유는 잔해에서 이미 겪었다 — 쏠 때마다 `SpawnActor + NewObject + RegisterComponent` 를 하면 그 프레임에 비용이 몰리는데, 미사일은 한 번에 두 발씩 공중전 내내 나간다. 사용자 제안(9/20)이 출발점: "드래곤 맞으면 다시 객체 풀로 재사용하면 되는 거 아니야? 함선에서?"
물리를 안 쓰는 이유도 같다 — 400cm 몸 수십 개를 Chaos 에 띄우면 NarrowPhase 가 다시 문제가 된다. 전용 메시가 없어도(모델링 대기) 안 보이는 채로 날아가 피해를 주고, 메시가 없을 때는 엔진 기본 도형(원통·원뿔·상자·구)으로 대신 조립해 궤도를 눈으로 확인할 수 있게 했다. 오후에 전용 메시가 들어와 기본 도형은 예비로만 남았다. 메시 피벗이 꼬리라 코끝이 액터 위치(=충돌 판정점)보다 4m 앞서 나가던 것은 몸을 길이만큼 뒤로 물려 맞췄다.

### 14-5. 드래곤

- **에셋**: Fab "Dragon for Boss Monster : PBR" 의 **SoulEater**(613 × 1029 × 578cm). 기획서 4-1 은 Usurper 였는데, 네 마리 중 TakeOff / FlyIdle / FlyForward / FlyFastForward / FlyAttack / Land / Scream / Die 가 **전부** 있는 건 SoulEater 뿐이라 바꿨다.
- **배율 4 → 14**(날개폭 약 145m, 체력 30000). 4 배(40m)는 410m 전함 옆에서 새처럼 보였다(사용자 9/20 "나란히 놔도 밀리지 않는 크기").
- **왜 `APGMonsterCharacter` 를 안 썼나**: 그쪽은 땅 길찾기·캡슐 이동이 전제다. 이 녀석은 하늘에서만 살아서 전함·미사일과 같은 "코드로 움직이는 액터"가 맞다. 피해만 UE 기본 `TakeDamage` 로 받아 주포·미사일이 그대로 통한다.

| 상태 | 내용 |
|---|---|
| Rising | 땅 90m 아래에서 시작해 뚫고 올라온다. 올라오는 동안 몸 둘레 소품·타일을 **0.15초마다 5개**씩 날린다(전함 이륙과 같은 예산 규칙) |
| Orbit | 전함 둘레 반지름 320m 를 45m/s 로 선회 |

| Landed | **체력 50% 에 한 번** 내려앉아 포효 5초 = 약점, 받는 피해 ×2(`bUsedWeakPoint` 로 한 번만) |

### 14-6. 날으는 차 (변신 스포츠카 + 부스터 키트)

**아케이드 비행 결정.** 이 차는 Chaos 바퀴 차량이다. 공중에서 힘을 주면 바퀴·서스펜션이 놀아 무게중심·토크가 제멋대로 작용해 "W 눌러도 어디 쏠리듯 날아갔고", 조용하면 Chaos 가 몸을 재워 입력이 죽었다. 오후에 세 번 고치다가(방향·깨우기·상승력) 결론을 냈다 — **부스터가 펴지면 물리를 끄고 코드로 움직인다**(전함·탱크·미사일과 같은 방식). 막히면 속도를 죽이고 땅에 닿으면 물리를 되돌린다(`EnterArcade/ExitArcade`).

| 입력 | 동작 |
|---|---|
| 마우스 오른쪽(누르는 동안) | 위로 22m/s. 부스터 펼치기 애니 1.17초 뒤부터 |
| W | **보는 방향**으로 40m/s(차 메시 앞축이 아니라 — 기울면 수평 성분이 0 이 됐다). 누르는 동안 초당 3.5m 씩 천천히 내려간다 |

| 상승 한계 | 땅 위 600m(전함이 이륙해 더 올라가도 쫓아갈 수 있게) |

서버가 움직이고 클라는 누름 상태만 보낸다(탱크·차 입력과 같은 방식).

### 14-7. 확인 방법 (PIE)

```
PG.SpawnBattleship [배율] [높이m]   전함 후보를 앞 하늘에 띄워 크기만 본다(로그에 길이·폭·높이 m)
PG.Finale.Start [경고초]           보스 안 잡고 시작. 0 이면 바로 산 너머에서 넘어온다
PG.Finale.Status                   단계·배 길이·나와의 거리
PG.Finale.Board                    갑판 위로 순간이동(승강 발판 약 9~12초 건너뜀)
PG.Finale.Launch                   갑판에 사람이 없어도 이륙 → 드래곤까지 확인
```
- 보스를 실제로 잡아도 시작된다(리스폰해도 피날레는 한 번만).
- 조종석에 서서 **V** = 1인칭/3인칭, **좌클릭** = 주포, **우클릭** = 미사일. 날으는 차는 **F** 로 연료통 → 변신 → 오른쪽 마우스로 이륙.
- 비행이 "안 나간다"면 1초마다 찍히는 로그 한 줄(up / fwd / deployed / air / sim / awake / height / speed)로 입력·펼침·잠듦·힘 중 무엇인지 구분한다.
- 헤드리스: `-PGObjectSmokeTest` → passed=50 failed=0.
