# 아이템 등급 표 (2026-09-22)

## 결론

- 등급은 **모든 아이템 공통 세 칸: 노말 / 레어 / 에픽**. 색은 노말 = 테두리 없음(맨 재질), 레어 = 파랑, 에픽 = 보라.
- **무기**는 같은 총을 세 등급으로 나눈다. 성능은 같고 **이름·색·값만** 다르다. 예: `Pistol`(권총 (노말)) / `Pistol_Rare`(권총 (레어)) / `Pistol_Epic`(권총 (에픽)).
- **무기가 아닌 아이템**은 아이템마다 등급이 하나다(값 구간으로 정함: 노말 1~999 / 레어 1000~2999 / 에픽 3000 이상).
- 등급·값·이름·맵 바닥에 떨어지는 비중·바닥 메시는 전부 **표 하나 `Docs/DT_PGItemValue.csv`** 에 있다. 표를 고치면 코드를 안 고쳐도 된다.
- 표끼리 맞는지는 `python Tools/check_item_tables.py` 가 빌드 없이 검사한다(9/22 결과: PASS, 오류 0).

## 2. 무기 등급

| 총 | 노말 값 | 레어 값 (x1.6) | 에픽 값 (x2.5) | 같이 떨어지는 탄 |
|---|---:|---:|---:|---|
| 권총 Pistol | 2600 | 4200 | 6500 | Ammo_Pistol |
| 리볼버 Revolver | 3400 | 5400 | 8500 | Ammo_Pistol |
| 샷건 Shotgun | 4200 | 6700 | 10500 | Ammo_Shotgun |
| 소총 AK Rifle_AK | 7800 | 12500 | 19500 | Ammo_Rifle |
| 소총 AR70 Rifle_AR70 | 9500 | 15200 | 23800 | Ammo_Rifle |

- ItemId 규칙은 옷 색 변형(Pants → Pants_Black)과 같다: 원래 ID = 노말, 뒤에 `_Rare` / `_Epic`. 원래 ID 를 안 바꿨기 때문에 기존 상자·퀘스트·무기 코드·스모크 테스트가 그대로 돈다.
- 성능: 레어·에픽은 원래 총의 무기 정의를 **복사해서 이름만 바꿔** 무기 컴포넌트에 넣는다(`UPGWorldLootSpawner::RegisterGradeWeapons`). 무기 코드(`Weapons/*`)는 고치지 않았다 — 공개 함수 `FindDef` / `RegisterWeapon` 만 쓴다.
- 바닥 메시: 레어·에픽은 표의 FloorMesh 칸을 비워 두고 원래 총 메시를 쓴다. 색은 **덧그리기(오버레이) 재질**로 테두리만 칠한다(아래 5번).
- 노말 AR70(9500)이 에픽 권총(6500)보다 비싸다 — 정상이다. "총의 급"과 "등급"은 다른 축이라 무기는 값 구간 검사에서 빼고, 같은 총끼리 노말 < 레어 < 에픽인지만 본다.

## 3. 어디서 나오나

### 맵 바닥(UPGWorldLootSpawner)

먼저 구역에 따라 등급을 굴리고, 그 등급 안에서 표의 "맵 바닥 비중"으로 아이템을 고른다.

| 구역 | 노말 | 레어 | 에픽 | 그중 총이 나올 확률(대략) |
|---|---:|---:|---:|---|
| 가장자리 | 90 | 10 | 0 | 약 9% |
| 중간(워존에서 4칸 안) | 75 | 23 | 2 | 약 15% |
| 워존 | 55 | 30 | 15 | 약 31% |

- 가장자리 에픽이 0 인 이유: 가장자리 칸이 워존보다 열 배 넘게 많아서, 1% 만 줘도 에픽 총 대부분이 가장자리에서 나온다. → **에픽 총은 중간·워존에서만** 바닥에 떨어진다.
- 에픽 등급 안에서 바닥에 떨어지는 것은 에픽 총 다섯 종뿐이다(희귀 재료·특수 열쇠는 금고·보스 전용).
- 총이 놓이면 그 옆 60cm 에 표의 AmmoItemId 탄 묶음이 같이 놓인다(레어·에픽 총도 원래 총과 같은 탄).
- 비중 숫자는 프로젝트 설정 > ProjectPG World Loot > Grades 에서 바꾼다.

### 상자·시체(루팅 테이블, `PGObjectSmokeTest.cpp` → `Docs/DT_PGLootTables.csv`)

- 무기 상자: 노말 다섯 종 + 레어(노말 비중의 0.4배) + 에픽(0.1배). 대략 노말 67% / 레어 27% / 에픽 7%.
- 군용 상자: AR70 노말 0.7 + AR70 레어 0.3 (에픽 없음).
- 보스(세력 C) 시체: AR70 **에픽** — 보스가 워존에 있으므로 "에픽은 워존" 규칙과 맞는다.

## 5. 표 고치는 법

1. `Docs/DT_PGItemValue.csv` 를 엑셀·메모장으로 고친다(UTF-8 유지). 열 이름은 바꾸지 않는다.
2. `python Tools/check_item_tables.py` → 끝 줄이 `RESULT: PASS` 인지 본다.
3. 에디터를 켜 둔 채면 콘솔에 `PG.ReloadItemTable` (또는 PIE 다시 시작 — 표는 처음 쓸 때 한 번 읽는다).
4. 같은 내용을 `PGItemValue.cpp` 의 `BuildFallbackRows`(예비 표)에도 반영한다. 검사 스크립트가 둘이 다르면 오류를 낸다.
   예비 표는 CSV 를 못 읽을 때만 쓰이고, 그때는 로그에 `using the C++ fallback table` 경고가 남는다.

읽는 순서: 프로젝트 설정 > ProjectPG Item Grades 의 DataTable 애셋(지정했을 때) → CSV 파일 → 예비 표.
CSV 에 문제(열 이름 오타, 없는 등급 이름)가 하나라도 있으면 예비 표로 넘어간다 — 틀린 칸이 조용히 기본값(노말·0원)으로 들어가는 것보다 낫기 때문.

등급 색 테두리 재질은 에디터에서 한 번 `Tools/make_grade_overlay.py` 를 실행해 만들어야 한다(`/Game/PG/Props/FloorItems/Materials/M_PGGradeOverlay`). 없으면 등급은 이름으로만 보이고 로그에 경고가 한 번 남는다.

## 7. 확인 못 한 것 [미검증]

- **빌드·PIE 안 함**(다른 세션이 빌드 담당). 컴파일 오류가 있을 수 있다.
- CSV 를 게임이 실제로 읽는지(`item_table_loaded_from_data` 스모크)와 UE 가져오기가 문제 0개인지 — 검사 스크립트가 같은 규칙을 흉내 낸 것일 뿐 UE 로 돌려 본 것은 아니다.
